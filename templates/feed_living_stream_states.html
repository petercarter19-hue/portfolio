Living Stream — page and state map

Every production mockup state from the Feed Vision Handoff v1, deep-linked into the connected prototype. Desktop states were designed at 1600×1000, tablet at 1000×900, and mobile at 430×932 — resize the window (or use device emulation) to review the responsive states.

Desktop states

No.StateHow to reach it in the prototype
01Living Stream defaultDefault view. No right rail; the stream stays centered.
02Photo / galleryGallery posts inside the same post shell.
03Video postMedia-forward video treatment in the same stream.
04Optional Catch Up railRail renders only when meaningful unseen updates exist; removing it recenters the stream.Interactively: the rail signal is a backend decision, so the default state deliberately has no rail.
05Voice listeningAlso: the composer mic, the Capture button, or mobile Capture. Cancel and “Stop and review” both work.
06Transcript reviewAlso: “Stop and review” from voice listening. Transcript is editable; audience and connections are selectable.
07AI-assisted publish reviewAlso: “Publish update” from transcript review. Publishing adds the update to the top of the Feed; “Keep private” saves without publishing.
08Conversation detailAlso: Comment on any post. Replies, Encourage, and Offer help work; the reply composer adds to the thread.
09Caught-up emptyAlso: the Following tab. One useful next action, no filler.
10LoadingHonest skeletons, held for review. The live prototype shows the same skeleton briefly on load and retry.
11Error recoveryPreviously loaded content stays visible; “Try again” really retries into the default stream.
