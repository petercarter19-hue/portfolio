# Active-Lane Compatibility and Transition

## Purpose and precedence

This record prevents already-released or already-assigned packages from
silently reintroducing the Capture-destination, private-draft-promotion, or
Journal-hold assumptions superseded by Bible v2.8 and Roadmap v2.7. It changes
no runtime and does not take ownership of another writer's files.

For target product behavior, this record and the current authority pointer
chain control. Earlier package statements remain valid evidence of what was
released, accepted, or planned at their dates; they do not become current
information architecture merely because an active writer reuses them.

## Owner Home frontend transition

`PS-HOME-FRONTEND-001` remains a separately assigned, default-off frontend
lane over the released finite `owner-home.v1` contract. Its current package
contains inherited references to:

- `capture_action.href` and `/app/capture`;
- a “safe Capture destination”; and
- a fixed `Home · Journal · Capture · Slate · More` mobile concept while the
  Journal was on hold.

Those references are not target information architecture. The Home writer may
preserve the real `/app/capture` link only as a truthful temporary,
default-off compatibility bridge to released behavior. That bridge:

- does not satisfy PS-JOURNAL J1 or J2;
- may not be presented as the approved final Capture route, page, tab, or
  navigation model;
- may not claim Save Moment, immediate derived Journal membership, or
  universal composer behavior that the runtime does not yet provide;
- may not fake a modal/composer or write around the shared source/Moment
  services; and
- must be recorded as a temporary product/visual deviation in Home evidence.

The Home writer must start from the post-authority `origin/main` tip, keep the
feature default off, and stop for designated-manager review before enablement
if the control still reads as a destination or the inherited navigation would
lock the route map. PS-JOURNAL J2 owns later replacement by the shared
context-preserving composer after its actual runtime contract exists.

## Capture Photo transition

The released Photo slice is valid flag-off history. Its current behavior saves
an owner-scoped private Capture/source and deliberately does not create a
Moment or Journal membership. That was truthful for its release, but it is not
the newly controlling end-state Save Moment contract.

Photo therefore remains disabled until a separately assigned package does one
of the following:

1. integrates Photo with the shared universal composer, authorized source and
   version preservation, one idempotent Save Moment operation, one private
   canonical Moment, and immediate derived owner-Journal membership; or
2. records an explicit owner-approved temporary exception with exact member
   language, duration, migration, data-rights, visual-truth, and retirement
   criteria.

Previously required lifecycle, two-owner, homepage-parity, and enablement
evidence remains necessary but is no longer sufficient by itself. No current
package authorizes enabling the source-only Photo journey as the final
member-facing Capture model.

## Projects transition

`PS-PROJECTS-001` remains planned future work. Its inherited “Journal UI is on
hold” statement is superseded: the Journal architecture is active and the
runtime private core is unassigned. Projects itself is not activated.

When Projects later passes its own entry gate, it consumes exact authorized
member-saved Moment references after Save Moment. It may not create a parallel
fact pipeline, copy Moment bodies, publish by completing a Project, or make a
Slate Board Project note silently create a canonical Project.

## Cross-lane release checks

Before Home enablement, Photo enablement, or later Project implementation, the
assigned manager and writer shall record:

- the exact post-authority base and the current compatibility rule used;
- whether any visible control still implies Capture is a destination;
- whether Save Moment and derived Journal behavior is truly implemented or
  explicitly absent;
- any temporary deviation, feature-flag boundary, migration/retirement plan,
  and member-facing truth label;
- two-owner authorization and payload-negative evidence where applicable;
- homepage parity impact; and
- Pete/designated-manager acceptance of the exact final behavior.

If an active package conflicts with this record, stop at the package boundary.
Do not edit another active writer's branch, invent unimplemented behavior, or
enable the feature while the conflict remains unresolved.
