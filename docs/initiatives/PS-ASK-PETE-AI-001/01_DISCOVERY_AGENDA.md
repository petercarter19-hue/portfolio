# Public Ask Pete AI / Ask [Name] AI Discovery Agenda

This agenda is for future public-profile assistance only. Private member asks,
voice, uploads, OCR, external documents, and Qualification Alignment belong to
`PS-ASK-SLATE-AI-001`.

## 1. Public visitor job

- Which questions should Ask Pete answer better than a static profile?
- Which approved public sources may support each answer class?
- When should it link to public Journal, My Story, Work, résumé, Project, or
  Studio without becoming a promotional rail?
- Which questions require “not in the public record” rather than speculation?
- How does the reusable Ask [Name] pattern let a member disable or correct it?

## 2. Answer anatomy

- direct answer first;
- public-safe source labels/links;
- separation of source fact and inference;
- missing/uncertain/conflicting public context;
- one relevant public next path at most; and
- no suggestion that a private source exists or was searched.

## 3. Authorization and abuse

- authorization before retrieval for every source/version;
- owner/public/audience changes invalidate search/grounding/cache;
- no private counts, gaps, timing, media paths, or source clues;
- prompt injection and source poisoning controls;
- scraping, rate-limit, abusive/impersonation query handling;
- report/contact and owner correction/disable;
- privacy-safe telemetry and retention.

## 4. Experience completeness

Prototype typed public use plus loading, long answer, no supporting source,
conflict, unavailable provider, rate limit, abuse refusal, source revoked,
mobile, keyboard, screen reader, 200% zoom, reduced motion, and homepage parity.

Public voice may be considered later as input convenience, but it cannot imply
signed-in identity, private Journal access, retention, or a separate assistant
persona.

## 5. Required output before a public refinement branch

- one bounded visitor scenario;
- exact public source classes and owner controls;
- accepted visual authority;
- authorization/retrieval/citation/abuse architecture;
- evaluation cases including unsupported/private questions;
- homepage impact;
- exactly one manager/writer/branch; and
- explicit implementation authorization.

The default remains **no new implementation**.
