# Destination and State Contracts

## Shared composition contract

All destinations inherit the same Profile identity, local navigation, viewer
resolution, and light editorial material system. One continuous working or
reading plane owns the page. Rails and sheets are contextual; they do not
compete permanently with the dominant object.

Every destination supports:

- zero, one, typical, and many-content states;
- initial loading, continuation loading, empty, no-match, dependency
  unavailable, object revoked, media failed, stale/conflict, and neutral
  unauthorized states;
- Owner, Connections, and Public behavior without leaking unavailable counts;
- direct deep links, Back/Forward, focus restoration, and stable scroll state;
- 320-pixel, 390-pixel, tablet, desktop, large-text, and long-content reflow.

## Home

- **Zero:** dignified identity/current-chapter page with only available deeper
  paths. Owner receives one private `Add something` invitation.
- **One:** one object may become Featured; no empty module placeholders.
- **Typical:** finite manifest defined in the purpose document.
- **Many:** Home remains finite; Manage Home selects and orders references.
- **Failure:** a failed optional module is removed or replaced by one quiet,
  audience-safe unavailable state; the rest of Home remains usable.

Home is never generated by a “latest activity” query at render time.

## Posts

- Displays Profile-eligible, authored Community post projections in reverse
  publication chronology.
- A Post shows exact audience, publication date, authorized attachment preview,
  and canonical `Open conversation` path when available.
- Profile does not copy comments. Previewed response counts are retrieved only
  from the viewer-authorized Community response.
- Zero Posts hides the Public destination; Owner gets `Write a post` and
  `Connect an existing Community post` choices only when real.
- Typical page size is 10. Many Posts use cursor pagination and authorized
  filters; never infinite unbounded DOM growth.

## Projects

- The first Project may receive a continuous editorial feature plane with
  role, period, outcomes, narrative, member-selected media, and exact related
  Post/Voice/proof references.
- Additional Projects use a compact ledger/list, not equal giant cards.
- Every Project is an exact released Project projection. Private Project work,
  Opportunity analysis, and Workshop Goals never enter the viewer payload.
- Public destination hides until at least one Project projection exists.

## Media

- The dominant object is a Featured album/collection or selected media item.
- `+N` is an actionable, keyboard-focusable path into the complete authorized
  album; it never hides inaccessible items inside the count.
- All Media, Albums, Photos, Videos, and member-created Collections are
  audience-filtered before counts and covers are selected.
- Many content uses cursor pagination and appropriately sized derivatives;
  source blobs and private metadata are never returned.
- Owner processing, failed upload, caption/alt-text, audience, placement, and
  source-change states attach to the selected object.

## Voice

- One selected recording owns the greatest area and persistence.
- List rows show title, date, duration, audience, and a compact play control.
- Selected playback includes semantic play/pause, scrubber, elapsed/remaining
  time, volume, speed, and readable member-approved transcript.
- No autoplay. One recording does not produce an empty filter rail. Hundreds
  of recordings use search/collection index and pagination, never hundreds of
  audio elements.
- Audio available/transcript failed and transcript available/audio revoked are
  represented honestly as separate states.

## About

- Contains Profile-specific identity, present context, principles/interests,
  and selected life-beyond-work orientation.
- It links to My Story and Résumé rather than reproducing either.
- Optional imagery collapses cleanly. Generated fixture portraits and text are
  never production defaults.
- Owner editing is contextual and private until the relevant audience revision
  is explicitly published.

## Local search and filters

Search appears only after an audience-safe index exists. It searches the
current Profile and current authorized audience only. No-match responses show
no hidden counts. Query/filter/sort state uses a safe URL representation,
preserves focus and Back/Forward behavior, and never exposes private terms in
server logs beyond the approved privacy taxonomy.

## Consequential and recovery states

The visual set's unpublish, source deletion, audience widening, unsaved edits,
publish failure, revoked item, stale source, processing, 320-pixel reflow, and
long-content boards are required implementation states, not optional polish.
Exact behavior is governed by the owner lifecycle and legal/trust documents.
