## Binding composition

The real protected Photo experience must preserve these recognizable Photo 1
qualities:

- deep-navy architectural frame around a warm ivory working stage;
- Newsreader editorial heading and Inter product copy;
- one dominant Photo Capture object and one dominant action;
- restrained marigold focus, provenance, and completion accents;
- visible `Private photo draft` status and plain-language trust explanation;
- calm architectural depth without parallax, auto-pan, or decorative motion;
- a purpose-built mobile document flow rather than a scaled desktop card; and
- a quiet return path to the existing Capture experience.

The selected board is production-intent design evidence, not a live-product
screenshot. It contains no member data and authorizes no publication, AI, OCR,
matching, destination, or cross-room behavior.

## Approved implementation adaptations

These adaptations are necessary to integrate Photo 1 with the real protected
Capture product and `06_EXPERIENCE_ACCESSIBILITY.md`:

1. The visual opens from a third first-class `Photo` choice beside the released
   `Type` and `Speak` paths. It does not replace those paths.
2. The mockup's compact rail is implemented as Photo-scoped modal context, not
   as a new permanent navigation system. The current owner shell remains
   upstream.
3. `Choose a photo` remains the dominant opening action. An additional
   `Take a photo` native camera path is provided where the device supports it;
   both paths converge on the same local `Not saved yet` review.
4. The decorative stone-arch depth is recreated with CSS geometry so it adds no
   public image dependency, member content, automatic motion, or alternative
   source of truth.
5. The complete backend-enforced states below extend the selected visual
   language. No unsafe or unscanned source receives a preview.

## Required-state implementation map

| Product state | Dominant object/action | Required truth |
|---|---|---|
| Opening | Photo intake / `Choose a photo` | Nothing selected, transmitted, saved, shared, or published |
| Local selection | Local preview / `Upload private photo` | `Not saved yet`; local-only until upload |
| Uploading | Bounded progress / `Cancel upload` | Upload may be stopped; server deletion is not claimed |
| Scanning | Private status stage / `Check status` | Original stored privately; no preview or Capture yet |
| Scan delayed/error | Recovery stage / retry or delete | Fail closed; Type and Speak remain available |
| Unsafe/rejected | Rejection stage / delete | No preview, confirmation, or downstream use |
| Safe review | Safe derivative + required note / `Save private Capture` | Embedded metadata removed; original retained privately |
| Validation/stale/unavailable | Inline recovery / correct or retry | No success claim and no lost private draft |
| Confirmed | Safe preview + confirmation / return to Capture | One private Capture exists; nothing shared or published |
| Draft deletion | Explicit confirmation / delete | Distinguishes local cancel from server draft deletion |
| Deletion retry/complete | Recovery or quiet completion | Success only after both private Blobs are absent |

## Accessibility and responsive authority

- Native file inputs remain in the accessibility tree.
- Every interactive target is at least 44 by 44 CSS pixels and has visible text
  or a precise accessible name.
- Focus moves to the current state heading, is trapped only while the Photo
  surface is genuinely modal, and returns to the Photo choice on close.
- Status uses a concise live region and never depends on color or animation.
- Mobile, landscape, 200-percent zoom, long note/error text, virtual keyboard,
  reduced motion, and no-JavaScript text fallback remain mandatory evidence.
- The local-preview alternative text is `Selected photo, not saved yet`.
- Server preview alternative text is neutral until the member supplies a note.
