## Purpose and boundary

Pete may open a new Codex session and attach the complete Direction A,
Editorial Studio Ledger Gate 2.4 design package. The session reviews and makes
the design evidence durable. It does not edit Interview Studio product code and
does not authorize implementation by itself.

- Review branch: `work/YYYY-MM-DD-interview-gate-24-review`
- Base: freshly fetched current `origin/main`
- Reviewer: bounded Codex manager-review session
- Receiving manager: Claude Co-Work
- Later feasibility/implementation writer: Claude Code, after all design gates
- Final visual acceptance: Pete and the designated session manager

## Required inputs

The attached package must contain or identify:

1. the nine separate full-screen current-public states from file `06`;
2. editable responsive source;
3. mobile portrait and landscape for written, review, video, history, and
   failure journeys;
4. focus, selected, disabled, loading, success, error, 200% reflow,
   reduced-motion, long-content, no-JavaScript, storage-unavailable, and
   media-unavailable behavior;
5. component and interaction-state inventory;
6. mapping to the boundary, experience/accessibility, and owner-approved scope
   files;
7. a truth/accessibility self-review and implementation concerns; and
8. the separate illustrative homepage Interview walkthrough, clearly separated
   from the real current-public Studio.

If any item is absent, review what was supplied and return `Conditional` or
`Fail`; do not invent the missing screen or quietly reduce the gate.

## Review matrix

For every required screen and variant, record:

- present and legible at production scale;
- aligned to Direction A and Deep Navy Gold semantics;
- one dominant practice object/action;
- truthful public-profile, browser-local, coaching-transmission, and local-media
  language;
- preserved current behavior and no invented authenticated/private capability;
- keyboard, screen-reader, focus, zoom/reflow, motion, responsive, long-content,
  and failure evidence;
- implementation mapping within the reserved template/CSS/JavaScript/test
  files; and
- deviations, conflicts, feasibility risks, or missing evidence.

## Writable review scope

- this initiative's Gate 2.4 review/evidence records;
- package-indexed design exports under the initiative or its already reserved
  artifact directory; and
- the standard completion report when closing the design gate.

Do not edit `templates/interview_studio.html`,
`static/css/interview-studio.css`, `static/js/interview-studio.js`, routes,
APIs, tests, auth, database, Capture/Moment, resume, navigation/theme, or
deployment configuration in the review session.

## Review result and handoff

Return `Pass`, `Conditional`, or `Fail` with the exact branch/full SHA, attached
asset index, complete matrix, conflicts, and single next action. Push the clean
review branch to Azure and give Claude Co-Work the durable report. Claude

to Claude Code for feasibility. Only after feasibility plus Pete/manager visual
