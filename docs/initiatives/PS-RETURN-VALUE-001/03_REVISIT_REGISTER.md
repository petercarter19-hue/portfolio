# PS-RETURN-VALUE-001 — Durable Revisit Register

## Status vocabulary

- **Committed — first slice:** architecture and near-term implementation intent.
- **Committed — later slice:** belongs to the product direction but follows
  prerequisites/evidence.
- **Revisit:** preserved option with a clear re-entry question; no current
  implementation promise.
- **Tabled:** intentionally inactive until an owner decision changes it.
- **Rejected current:** conflicts with current trust/product direction; source
  remains recorded but may not be implemented under another name.

## Re-entry rule

An item moves out of Revisit/Tabled only when a new owner decision names:

1. the user problem and evidence;
2. why the existing committed services do not already solve it;
3. exact privacy, safety, audience, and lifecycle boundaries;
4. its relationship to Journal and canonical Moments;
5. success and anti-pressure measures;
6. accessibility and failure behavior;
7. a designated manager, single writer, branch, and accepted visual authority;
   and
8. what is removed or simplified if the idea adds visible complexity.
