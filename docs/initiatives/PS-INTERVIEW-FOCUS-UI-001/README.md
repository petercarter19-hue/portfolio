### Narrow authority adjudication: Interview AI follow-ups

The V3 authority both preserves the existing request contract and requires a
follow-up result to remain associated with the same selected evidence basis. The
released frontend forced every follow-up to `member_history`, even after an initial
`best_practice` or `compare` result, which silently contradicted the selected basis
and its provenance label.

For this initiative, the frontend therefore sends the currently selected,
already-supported `mode` enum value for both the initial request and its follow-up.
This is a narrow truth/provenance correction under Pete's approved V3 authority:
the endpoint, JSON field names, accepted values, signed context token, backend,
prompts, rubrics, provider, and response contract are unchanged. No new API
capability or backend behavior is introduced.
