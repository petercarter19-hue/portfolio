# PS-MESSAGING-001 — Member Messaging

**Status:** Committed future capability; architecture recorded, implementation
not active

**Owner direction:** July 20, 2026

**Roadmap timing:** After trusted identity, Connection/consent, block/report,
notification, retention/deletion, moderation/support, and legal gates

**Runtime writer:** Unassigned

**Runtime truth:** Comments/responses are not direct messaging, and this package
does not claim an inbox or message delivery is live.

## Product role

Messaging allows permitted people to communicate privately in relation to work,
growth, a shared connection, or an explicitly shared PeerSlate object. It is
not a public attention channel, an unsolicited recruiter funnel, or an AI agent
that talks to people for the member.

## First intended scope

A later first slice should be consent-based one-to-one text messaging between
eligible connected members, with block/report/mute, notification controls,
retention/deletion, and optional authorized Moment reference. Group chat,
attachments, calling, public-profile cold DMs, and AI automation are later or
excluded.

See `01_ARCHITECTURE_AND_SAFETY.md`.
