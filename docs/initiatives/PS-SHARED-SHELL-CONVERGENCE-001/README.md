# PS-SHARED-SHELL-CONVERGENCE-001

## Outcome

This Protected package converges PeerSlate's established shared shell across
public and authenticated routes. It starts after the neutral My PeerSlate
launchpad retirement and does not redesign any product room.

One server-rendered destination description now drives the desktop row,
medium-width room switcher, mobile sheet, navigation-only search, signed-in
phone bar, and native no-JavaScript fallback. Existing availability flags
remove a destination from every representation together. Protected-route
classification still controls search scope and access behavior, but no longer
selects a second header implementation.

The account shell consistently exposes only My PeerSlate, Settings, and the
existing POST Sign out action. Workspace-waking, account-issue, signed-out,
safe-return, authorization, private/no-store, and robots behavior remain
unchanged. The legacy owner-only search and mobile scripts are retired after a
repository-wide reference proof.

## Narrow corrections

- The homepage describes Interview Studio as sign-in-gated and labels Pete's
  public project evidence without implying a member Projects capability.
- Skills and Contact own their page H1; the repeated Pete identity label is
  presentational text there. About and Hobbies retain the profile-band H1.
- Shared controls have visible keyboard focus, 44px minimum targets, forced-
  colors and reduced-motion treatment, safe disclosure focus restoration, and
  320px/200%/400% reflow.
- Workshop no longer receives an orphan shell Ask-AI path. Its page-local UI,
  current visual direction, and separate reflow/accessibility backlog are
  unchanged.

## Boundaries

This package does not edit routes, authentication, safe-return logic, identity,
schema, data, services, flags, Workshop or Interview-local templates/CSS/JS,
Projects/Profile capabilities, or the dormant dark theme. It performs no
deployment, enablement, production verification, identity action, or live
operation. Repository merge is not deployment.

## Acceptance

Acceptance requires the exact claimed route/state matrix, full repository
regression, package-registry validation, dead-reference and secret scans, and
local synthetic captures at desktop, medium, tablet, phone, 200%, and 400%
reflow. Captures must include JS-off, forced-colors, reduced-motion, search,
account, room-switcher, Menu/More, and recovery states. A fresh independent
review must accept one immutable candidate SHA before receipt/evidence tail and
merge.
