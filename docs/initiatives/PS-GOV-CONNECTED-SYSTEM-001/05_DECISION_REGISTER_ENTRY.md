## Supporting record (not appended to `DECISIONS.md`)

### Context

Bible v2.6 already established one connected Slate and create-once/place-many as
constitutional. The gap the owner identified is experiential, not architectural:
the relationship between rooms is real in the data model but invisible in the
product. Separately, PeerSlate had no governing position on why a member returns
— which left an open door for engagement mechanics that contradict PS-P-001 and
PS-P-009.

### Alternatives considered

| Alternative | Why not chosen |
|---|---|
| Add a global "Insights," "Memories," or "Engagement" destination | Directly violates PS-P-014 and the CONSOLIDATE-DO-NOT-PROLIFERATE navigation rule. It also makes the trunk weaker, not stronger, by moving connection out of the rooms it belongs to. |
| Add generic "related content" rails to every room | Cheap to build and hostile to the product thesis. A rail without a governed relationship is promotion, not connection, and would invite fabricated links. |
| Use streaks and progress gamification to drive return | Explicitly rejected. It contradicts PS-P-001, PS-P-009, and the member service covenant, and it would compensate for an incomplete owner loop rather than complete it. |
| Build the proof graph as a new aggregate and system of record | Creates a second truth store, contradicts `PS-CORE-DATA-001` and the CANONICAL-TRUTH RULE, and duplicates what `PS-PLACEMENT-001` already delivers by reference. |
| Defer the decision until the owner loop is complete | The connective and return-value questions shape Owner Home, Replay, Studio, and the public pilot. Deciding late would mean rework or accidental precedent set by whichever package shipped first. |

### Risks and mitigations

| Risk | Mitigation |
|---|---|
| Connective elements slow or clutter the primary task | `PS-CORE-NFR-008` requires primary-task speed and comprehension to be preserved and measured; the connective budget is capped at one primary and two secondary actions. |
| A room fabricates a relationship when none exists | The logical contract makes an empty render correct and a fabricated relationship a defect; `PS-CORE-DATA-007` forbids copied facts. |
| Private context leaks through a connective payload | `PS-CORE-IA-014` forbids client-side filtering; authorization-before-retrieval applies unchanged; the event taxonomy forbids content logging. |
| Preservation is mistaken for authorization | `PS-CORE-GOV-008` requires an explicit status on every connective idea; the Experience System section carries an all-`no` status ledger. |
| Return-value work drifts into engagement mechanics | `PS-CORE-VAL-005` and PS-P-016 name the prohibited mechanics explicitly, and the rejected-for-current-program list is constitutional. |
| Documentation-stage language is read as a shipped capability | Every candidate file carries a PROPOSED banner; no pointer file was changed; the architecture section states current per-layer reality at the exact base SHA. |
