## Candidate board plan

The missing-state set is consolidated into six production-intent boards:

1. **Feed availability and completion** — desktop/mobile loading, truthful
   new-member empty, partial module failure, full unavailable/retry, and finite
   caught-up behavior.
2. **Composer and publication** — focused composer, explicit audience,
   response posture, Spark, attachments, processing, preserved-text failure,
   and truthful success.
3. **Search, shell, and signed-out truth** — Community search results, empty,
   permission/failure, mobile search, and a signed-out read-only public Feed.
4. **Conversation lifecycle and safety** — selected/full conversation loading,
   long content, pagination, edited/deleted/moderation-held/revoked truth, and
   permission denial.
5. **Visible actions and messaging truth** — Respond intentions, save state,
   author/viewer menus, contribution actions, file outcomes, and unavailable
   messaging.
6. **Responsive, theme, and mobile module disposition** — mobile full thread,
   Community activity/questions sheet, 200% reflow, keyboard focus,
   reduced-motion cue, and dark theme.

## Accepted public-pilot product dispositions

- The first runtime slice has one finite default Feed; `Following`, `Recent`,
  and a separate `Questions` filter are hidden/deferred rather than invented.
  Question posts remain ordinary Feed items and Active Questions remains the
  bounded module from the locked desktop authority.
- Pete's first production pilot is owner-authored and publicly readable. The
  initial authorized author must sign in; drafts remain visible only to that
  author; publication requires an explicit `Public` choice and confirmation;
  signed-out visitors may read only published public posts. Public is never a
  default chosen by opening the composer, and widening or changing an audience
  after publication remains prohibited in V1. Community-member,
  Connections, selected-person, and other audiences are deferred.
- Community search is retained because it is visible in the locked desktop and
  mobile shell. Results authorize before returning any text, counts, identity,
  or media.
- Mobile Pulse/Questions recompose into a subordinate `Community activity`
  sheet, not a third first-class Community route.
- The existing site theme contract remains supported; dark mode changes tokens,
  not hierarchy or composition.
- `Message` remains visible only as an honestly unavailable disabled action
  with a short explanation until a messaging package ships.
- Respond retains the five owner-approved intentions: Celebrate, Support,
  I relate, Ask, and Offer help. It is non-ranking, replaceable, and removable.
