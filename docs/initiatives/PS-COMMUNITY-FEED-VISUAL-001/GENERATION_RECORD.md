# Community Feed visual generation record

## Method

- **Mode:** built-in image generation tool
- **Use case:** `ui-mockup`
- **Project-bound outputs:** copied from the generated-images store into the
  candidate directory; original generated files retained
- **Reference role:** the six Pete-locked Community images were style,
  composition, interaction, and invariant references; no locked file was an
  edit target

## Final prompt set

Each prompt required a production-intent landscape 2x2 state board matching
the Deep Navy Gold, white/light canvas, restrained blue, warm Spark accent,
editorial typography, rounded cards, and desktop/mobile composition of the
named locked references. Every prompt prohibited jobs, popularity/ranking,
decorative polls, fake live claims, new routes, watermarks, and redesign of the
locked journey.

1. **Feed availability and completion** — desktop loading with three-column
   skeletons; desktop Community Pulse-only failure with usable Feed; payload-
   free mobile new-member state with `Your community starts here`; desktop
   full unavailable state with truthful retry and no loss claim.
2. **Composer and publication** — desktop private draft with explicit
   `Community members` audience and response posture; mobile Spark-attached
   draft with image/file processing; desktop upload failure preserving text;
   mobile return-to-Feed success labeled `Published to Community members` and
   no invented engagement.
3. **Search, shell, and signed out** — authorized desktop results; mobile no-
   result state; bounded desktop search-unavailable state with usable Feed;
   payload-free signed-out sign-in screen. A targeted edit removed an invented
   bottom navigation bar from the mobile panel and preserved all other pixels
   as closely as the tool allowed.
4. **Conversation lifecycle and safety** — desktop selected-detail loading;
   full conversation with Edited, deleted, under-review, and source-unavailable
   truth; long paginated mobile conversation; payload-negative mobile
   permission denial.
5. **Visible actions and messaging truth** — five non-ranking Respond
   intentions with Celebrate selected; separate author/viewer permission menus;
   mobile Save failure recovery; desktop disabled Message action with
   `Messaging isn’t available yet.` A targeted edit removed an unrelated author
   menu from the active Respond panel.
6. **Responsive, theme, and mobile modules** — mobile subordinate Community
   activity sheet; 200% reflow with collapsed rail functions and one horizontal
   Replies & updates row; Deep Navy Gold dark theme preserving hierarchy;
   landscape/large-text selected reply with no clipping and unavailable Message.

## Validation result

All final workspace candidates were visually inspected at original resolution.
The final two edited boards were re-inspected after correction. Exact hashes,
dimensions, and byte sizes are in the candidate manifest. Text shown in a
raster remains visual copy authority only after Pete accepts the exact file;
runtime implementation must use semantic HTML and the package's truth and
accessibility contracts rather than rasterized text.

## Owner-directed public-pilot revision

Pete subsequently directed that he must be able to build the Feed with real
content and view the published result on the actual public website, even while
he is the only initial author. The built-in image-generation edit path produced
a non-destructive revised candidate set under
`visual-candidates/2026-07-31-chatgpt-public-pilot/`.

- **Board 01 edit target:** changed only the selected audience and publication
  truth to `Public`, `Anyone can view this post`, `Published publicly`, and the
  `Public` composer chip while preserving the private-draft lock and explicit
  Publish action.
- **Board 02 edit target:** replaced only the signed-out sign-in wall with a
  read-only public Feed state. The public post stays visible, the visitor is
  told `Anyone can read public posts. Sign in to participate.`, and no signed-
  out authoring or interaction action is shown.
- **Boards 00, 03, 04, and 05:** copied byte-for-byte from the first completion
  set because the public-pilot decision does not change their state contract.

The exact built-in edit prompts constrained both outputs to the original board
composition and prohibited autosave, automatic publication, AI, messaging,
fake metrics, new routes, and hidden private payloads. The revised boards were
inspected at original resolution; hashes, dimensions, and bytes are recorded in
their adjacent `MANIFEST.md`. They remain candidates until Pete accepts those
exact files.
