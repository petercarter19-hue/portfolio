# PeerSlate Roadmap

**Version:** v3.0 — lean sequence authority
**Status:** Current and owner-directed on 2026-07-31
**Historical detail:** Roadmap v2.8 remains preserved for prior package
provenance and detailed historical rationale.

## What this document does

The Roadmap states order and dependencies. It does not repeat feature
requirements, implementation plans, tests, release facts, or the active-writer
register. Those belong to the task brief, evidence record, and control plane.

## Direction

1. Preserve the current site and its truthful public boundaries.
2. Strengthen the private member foundation: trusted identity, canonical
   records, authorization, Save Moment, and the private Journal.
3. Make the record useful: focused Studio/activation, careful return value, and
   governed reuse through Story, Work, Projects, and approved projections.
4. Expand connection, AI, public expression, and business scope only after the
   relevant private, authorization, and member-value evidence exists.

## Current sequencing rules

- A future idea does not block an independent, safe, bounded task.
- A package may begin when its direct dependencies and safety controls are
  ready; it does not wait for unrelated historical phases to be declared
  complete.
- A new page strengthens an existing room unless an owner decision explicitly
  creates a new product domain.
- Public/broad-audience, identity, data, publication, deletion, consequential
  AI, and infrastructure work use the protected delivery path.
- Work is deferred only when it lacks its own needed authority, conflicts with
  an active writer, or would violate a constitutional boundary.

## Portfolio order

| Now | Next when its direct package is ready | Later, after evidence |
| --- | --- | --- |
| Preserve current public truth; private Journal foundation; approved Studio and owner-work direction | Focused activation/return value; governed Story, Work, and Project reuse; exact public projection work | Broad community, advanced AI, Qualification Alignment, integrations, monetization, and scale |

The control plane names active lanes and blockers. Each task brief names its
own direct dependency and one next action. No separate global phase gate may
block unrelated routine or bounded work.
