# PeerSlate Codex task launcher

This convenience launcher is not repository authority. Current root
`AGENTS.md`, `START_HERE.md`, the package claim, and the authorities they point
to control. Read them from current Azure `origin/main`; do not copy this
launcher into another policy file.

Paste the following into a new Codex task:

> Work on PeerSlate under current root `AGENTS.md` and `START_HERE.md`. Identify
> the exact package, task reference, assigned role, manager, branch, claimed
> surfaces, delivery path, and next authorized outcome before writing. Select
> the role's current model and effort from
> `docs/AI_MODEL_AND_ROLE_ROUTING.md`, then verify the effective setting in
> this task. If it cannot be inspected, report it unavailable; do not infer it
> from the handoff or churn a setting that is already correct.
>
> Preserve unrelated work. Use the registered package worktree and required
> preflight. For implementation, continue through tests, complete-diff
> self-review, accepted corrections, required exact-SHA independent review,
> Azure PR, accepted merge, evidence, claim close, and eligible lifecycle
> cleanup. Deployment and production remain separately authorized.
>
> Report meaningful state changes, decisions, failures, completion, or
> required owner action. Do not create acknowledgement loops, duplicate
> reviews, unrelated audits, cache warmers, or status-only monitoring.
>
> A complete authorized transfer to another supported platform may give its
> accepted manager the bounded package through closeout without a Codex
> supervisor. Verify the receiving task, platform/account/project access,
> exact repository source, model/effort, and explicit acceptance. Never
> transfer credentials, cookies, MFA, tokens, browser state, or session-only
> authority.
